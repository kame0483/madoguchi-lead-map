# 案件エリアマップ

既存の GitHub Pages + Supabase `lead-map-api` を継続する営業用画面です。

- フロント: https://kame0483.github.io/madoguchi-lead-map/
- 既存の `?k=...` 付き閲覧URLを使用してください。キーをコードやREADMEへ記載しないでください。
- `pref=岡山県` で県内表示、`pref=岡山県&city=岡山市北区&r=40` で周辺検索から開始できます。既存キーのパラメータに追加します。
- 地図表示が重なる場合は拡大、都道府県選択、47都道府県の件数一覧から選択できます。

## 集計

`estima_ingest_log` の `fn=lead`、`gaiheki`／`amamori` を対象とします。まず同一 `eid` の最新履歴を確定し、その後に有効／審査中、2025/12/01以降、地域条件を適用します。`eid` がなければ種別・申込日時・地域・住所のハッシュで重複除外します。同時刻の更新はログIDと行順で確定します。

全国・都道府県・市区町村・距離検索・一覧は `lead_map_dataset_v2` を共用します。最初に取得したスナップショット日時をページ分割にも渡し、閲覧途中の更新による合計のずれを防ぎます。「更新」で最新状態を取得します。日付の境界は日本時間、本日追加は受付日当日、直近7日は当日を含む7暦日です。

2026/11/13検証時: **5,237件 = 外壁4,979件 + 雨漏り258件**、本日16件、直近7日127件。旧5,321件には、最新状態が無効の84件が過去の有効履歴から混入していました。コードにこれらの案件数は固定していません。

8,123は管理画面の2026/11/13確認値であり、自動更新できる取得元は未接続です。案件数とは別の補助指標として確認日とともに表示します。

## 個人情報と認証

- APIはマスク済み電話番号だけを返します。メール・生の顧客オブジェクト・姓未分離のフルネームは返しません。
- 氏名は空白で姓を分離できる場合のみ表示します。判別できなければ「お客様」と表示します。
- 物件情報は許可リストの項目だけを返し、自由記述内の電話番号・メールもサーバー側で除去します。住所は依頼された仕様により表示します。
- RPCは `service_role` のみ実行でき、フロントから直接実行できません。新規関数は SECURITY INVOKER です。
- 既存の閲覧キー照合を維持。新しい画面はキーをAPIのヘッダーに渡し、APIリクエストURLへ追加しません。外部リソースへのRefererはoriginだけに制限します。
- 本番の `access-config.ts` は非公開のデプロイ設定です。公開リポジトリへ保存しないでください。`access-config.example.ts` は環境変数から読む設定例で、既存本番の値を上書きする手順ではありません。
- Edge Functionの再デプロイ時は、現在の非公開設定を保持し、`index.ts`、`access-config.ts`、`deno.json` を含めます。JWT検証は既存同様offで、関数内で閲覧キーを検証します。

現在の共通キーでは会社単位の識別・認可はできません。次段階は、会社ID・許可地域・有効期限をサーバー側で管理する失効可能な個別トークンです。URLの会社名だけを変更する方式では、会社の特定も閲覧権限の保護もできません。CTA計測はその識別基盤と合わせて追加してください。

## 画面・設定

- 初回は都道府県マーカーと集計のみ。市区町村座標は県ごとのJSONを必要な時に取得します。
- 距離検索では検索用の地名一覧と、円に接する都道府県だけを取得します。同名自治体は選択肢で確認し、ゼロ件を全国検索へ置き換えません。
- 全国・県内・周辺の案件一覧は50件ずつ取得。APIは空ページでも総件数を返します。
- APIの`cases`はPOSTの`keys`配列を推奨。従来GETも互換対応しています。120地域の切り捨ては廃止しました。
- Leaflet 1.9.4 / OpenStreetMapを継続。タイル取得が失敗した場合のみ地理院タイルへ切り替え、出典も更新します。
- 各案件の「この案件に対応したい」「条件を聞きたい」は、電話連絡の受付画面を開きます。Googleカレンダーの正式予約URLは接続済みです。自動メール送信は下記の有効化待ちです。
- 会社別閲覧権限・ログインは未実装です。匿名の訪問履歴・CTAクリック計測と管理画面を追加しています。

## 地理データ

`assets/geo/` は [code4fukui/localgovjp](https://github.com/code4fukui/localgovjp) の自治体代表座標（CC0）を県別に分割したものです。取得元CSVのSHA-256をindex.jsonへ記録しています。浜松市の中央区・浜名区は従来の中区役所・浜北区役所の代表座標を引き継ぎ、旧区名を更新しました。郡名・三宅島／八丈島の表記差を照合します。案件や顧客の住所データを含めていません。


## お問い合わせの通知（FormSubmit）

2026/11/13、ユーザーの承認により社内通知のみへ簡略化しました。フロントの `contact.js` が FormSubmit の AJAX endpoint に送信します。送信先は `t.kamei@madoguchi.inc` 固定です。Supabase／SendGrid の追加設定や亀井側プロジェクトへの移行は不要です。案件取得API・認証・集計には変更していません。

- 用件: 対応希望・条件相談・資料請求・無料トライアル相談。
- 必須: 会社名、担当者名、電話番号、メールアドレス。希望日時は任意。
- 通知内容は入力した業者の連絡先・用件・案件ID・種別・受付番号・希望日時だけです。元案件の顧客氏名、住所、電話、メール、閲覧キーを含めません。送信時のRefererはoriginに制限します。
- FormSubmit経由で通知することを入力フォームに表示しています。自動返信メール・資料添付・契約確定は行いません。送信後のWeb予約リンクを維持しています。
- 通知のメール到達はproviderの受付成功だけでは保証できません。失敗・初回認証待ちでは完了画面を表示しません。送信中の重複操作は抑止しますが、旧サーバー側のUUIDによる重複除外は使いません。通信結果が不明な場合の再送には注意が必要です。
- 初回確認: `notification-setup.html` を通常のブラウザで開き、FormSubmitの案内に従って、届いた確認メールを認証してください。
- 作業環境からの接続確認はFormSubmit側のアクセス制限（403）で拒否されました。認証メール送信／実メール到達は未確認です。アプリの送信処理はモックで検証しています。
- FormSubmitはフォーム送信データを30日保持する旨を公開しています: https://formsubmit.co/documentation

旧 `supabase/functions/lead-map-api/contact.ts` とDBの受付テーブルは残していますが、現行フロントからは呼びません。既存Supabase設定の変更は不要です。

### サンクスページと希望時間（2026/11/13更新）

- 成功応答を確認した場合にのみ `thanks.html` へ移動します。フォームの入力エラーと送信失敗は、フォーム上のエラー欄へフォーカス・スクロールして表示します。
- 自動入力された隠し項目で無言停止する分岐を削除しました。実際のユーザー環境での原因の断定はできません。FormSubmit標準の対策設定は変更していません。
- 希望時間は9〜21時の範囲を1時間ずつ区切った12枠（9〜10時から20〜21時）を、ラジオボタンで選択します。日時は確定予約ではありません。
- サンクスページで用件・希望日時・受付番号と、資料を共有するWeb打ち合わせの予約リンクを表示します。
- 連絡先を遷移URLへ含めません。同一タブのsessionStorageへ受付番号・用件・希望日時だけを保存し、連絡先や閲覧キーは保存しません。戻る操作はブラウザ履歴を使い、元の閲覧URLへ戻します。
- モックのスマホ操作で入力不足表示と時間選択→送信成功→サンクスページを確認しました。FormSubmitの実送信は作業環境からアクセス拒否されるため、この修正版からの実メール到達は未確認です。初回設定用の確認メール到達は受信箱で確認済みです。

すべての問い合わせフォームの通知件名は `【資料ダウンロード】用件 / 会社名` です。対応希望・条件相談・資料請求・無料トライアル相談の実際の用件を残して区別します。通知先は `t.kamei@madoguchi.inc` 固定。実ファイルのダウンロード完了を計測するイベントではありません。


### 一覧の絞り込みと今すぐ希望（2026/11/13更新）

- 案件一覧は受付日の新しい順で最初の10件、追加も10件ずつ取得します。地図・地域全体の件数は維持し、絞り込み後は一致件数を別に表示します。
- 「案件を条件で絞り込む」を開いた時だけ、その地域にある項目と値を取得します。案件種別・受付期間・工事内容・築年数・建物・階数・工事予定・見積取得・外壁材など、既存の公開許可済み項目を複数指定できます。同一項目は1つ、異なる項目はAND条件です。件数は読み込んだ10件ではなくエリアの全案件に対して照合します。
- SQLは `sql/lead-map-case-filters.sql`、APIは `case_filters` と `lead_map_page_v3` を使用します。既存の共通データセットとスナップショットを維持し、新RPCはservice_roleのみ実行できます。
- 「今すぐの連絡を希望」を選択した場合、希望日を解除し、通知とサンクスページに今すぐ希望を表示します。即時の架電や確定予約を保証するものではありません。
- 10件追加時に画面の高さが変わって操作位置がずれないよう、カードの描画省略を解除しました。データの段階取得は維持しています。
- 問い合わせ振り分け用シートのGmail検索条件は従来の問い合わせだけに戻しました。このサイトのCVはGAS経由ではなく、受付APIから直接Google Chatへ送信します。既存の振り分け率と他サービスの取り込みには変更していません。


### 通知先と利用状況管理（2026/11/13更新）

- このサイトのメール通知先は **t.kamei@madoguchi.inc のみ**です。共有メールボックスを宛先・CC・BCCに使用しません。メール件名の「資料ダウンロード」と各用件の区別は維持しています。
- `conversion_submit` が既存の非公開受付テーブルへ保存し、Google Chatの既存問い合わせスペースへ直接通知します。FormSubmitメールの取り込みトリガーには依存しません。Chatテスト送信でAPIの送信成功応答を確認済みです。
- 受付UUIDで再試行を照合します。Chat送信成功済みの受付は、メール再試行で重複通知しません。Chat失敗でも受付記録を保持し、管理画面から明確に失敗した通知を再送できます。結果不明の場合は重複防止のため自動再送しません。
- メールはブラウザからFormSubmitの亀井宛endpointへ送信します。`email_ack_at` はブラウザがprovider成功応答を確認した時刻で、受信箱への到達証明ではありません。作業環境のFormSubmit制限のため、この変更後の亀井の受信箱への実着信は未確認です。ユーザーが以前この宛先で受信した実績があります。
- `activity.js` は正規の閲覧キーで開いたページについて、匿名タブセッション・アクティブ閲覧時間・定義済みのボタン操作・表示エリア・絞り込み項目を記録します。自由入力の検索語、連絡先入力値、閲覧URL、閲覧キー、IP、User-Agent、画面録画は保存しません。CV送信後だけ受付と訪問IDを関連付けます。
- 表示中かつ60秒以内に操作がある時間を、15秒ごとに累積値で送信します。離脱や通信で最後の秒数を失う場合があり、厳密な読了時間や実人数ではありません。再送されたイベントIDは重複除外します。
- `admin.html` は直近1/7/30日の訪問数・ページ表示・閲覧時間・ボタン集計・最新100訪問の足跡・最新100CVと通知状態を表示します。`admin_*` APIは閲覧キーとは別のランダムな管理キーを要求します。匿名・通常閲覧者は管理データを取得できません。
- 管理キーはURLのfragmentで受け取り、すぐURLから除去してタブのsessionStorageに保持します。サーバーにはハッシュのみを保存します。管理者用URLは社内管理者だけに渡し、加盟店へ送らないでください。キーの更新はサーバー側のprivate config更新が必要です。
- `notification-config.ts` のChat webhookと管理キーハッシュはEdgeの非公開デプロイだけに含めます。Gitに保存するのは空のexampleのみです。今後のEdge再デプロイ時には、このprivate fileと既存 `access-config.ts` を必ず保持してください。
- 公開フッターに計測内容を記載しています。過去の操作履歴は復元できません。会社別のURL識別には任意の `company` パラメータ（英数字・ハイフン・アンダースコア64文字以内）を使えます。自己申告可能なコードのため本人確認や会社別認可には使用しません。


### 会社別URLで問い合わせ前に識別（2026/11/13更新）

- 管理画面の「一斉メール用の会社別URLを発行する」で、会社名・メールアドレスの2列をCSV/TSVまたは貼り付けで登録できます。管理者専用APIに200行ずつ送信し、DBがランダムな32桁IDを発行します。同じ会社名・小文字化したメールは既存IDを再利用します。ここからメール送信は行いません。
- 閲覧可能な既存URLを管理画面に入力し、各社URLをブラウザ内で作成します。DBへ閲覧キーやURLは保存しません。URLに追加するのは `company` 識別IDだけで、会社名やメールアドレスを含めません。初期エリアのパラメータは引き継ぎます。
- 各社URLをメール本文へ差し込むと、フォーム未送信でも管理画面に送付先会社名、閲覧時間、ボタン操作、CVを表示します。問い合わせで申告された会社名とは別に、専用URLの送付先であることを表示します。共通URLの場合は匿名です。
- 同じタブで異なる会社のURLを開いたときは新しい訪問IDに切り替え、会社間で履歴を混同しません。識別コードと会社の対応表は管理者だけが取得でき、通常の閲覧キーからは読めません。
- 「会社ごとの反応」はアクセスとボタン操作を分けて表示します。メール側の自動URL確認、URLの転送・共有などがあるため、個人の本人確認や実人数を保証しません。フォーム入力の省略による本人認証の代わりにはしません。
- CSVの出力は会社名・メール・各社URLの3列です。元の送信リストへ追加する場合は、メールアドレスと対応付けてURL列を差し込んでください。数式から始まる会社名はCSVでエスケープし、特殊記号から始まるメールアドレスは変更せず、CSV自動出力を止めて元シートへのURL列転記を案内します。
- 実際に送信するリストはまだ提供されていません。実在の送付先登録・各社へのメール送信は未実施です。テスト用のDB登録・クリック履歴はトランザクションをロールバックし、検証データを残していません。


### メールなし業者の識別（2026/11/16更新）

- URL発行のメールは任意です。メールなしの場合は会社名＋安定した会社ID（MF等）または電話番号を使います。会社名だけでは同名会社の混同を防げないため登録しません。電話番号の全角・ハイフン・+81形式を正規化します。
- CSV/TSVは従来の会社名・メール2列に対応したまま、会社名・メール（空欄可）・会社ID／電話番号の3列、または見出し付きの会社名・会社ID（電話番号）2列を受け付けます。
- メールありは会社名＋メール、メールなしは会社名＋会社IDで既存IDを再利用します。メールの有無を変更した既存登録は自動統合しません。既存の会社コード・足跡・メール必須のCVフォームは変更しません。
- 専用URLはSMS・LINE等への共有用にコピーできます。電話番号や会社IDはURLに埋め込まず、ランダムなcodeだけを追加します。共通URLからの訪問は匿名で、会社・個人をIP等から自動特定する機能はありません。
- メールなしも管理画面で会社名・ID・閲覧時間・ボタン操作を確認できます。CSVは既存の会社名・メール・URLの3列を維持し、会社IDがある場合だけ4列目に追加します。
- 一斉送信GASの既存コードへの組み込みはGoogleログイン待ちです。この変更で送信リストの更新・GASの編集・業者へのメール/SMS/LINE送信は行っていません。
